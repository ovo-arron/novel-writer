# Three-Core Orchestration

Use this reference when a request crosses conception, prose, revision, import, research, or persistent project memory. It defines the contract among Core I, Core II, and Core III without turning them into three mandatory reports.

## 1. One loop, variable depth

Use:

```text
Core III retrieves evidence → Core I chooses or diagnoses movement
→ Core II realizes the requested artifact → Core III audits and stages a delta
```

Every core participates, but participation may be one sentence or a full workflow. Do not expose the internal loop unless analysis is requested.

| Task | Core I depth | Core II depth | Core III depth |
|---|---|---|---|
| One-off premise | deep | concise presentation | ephemeral/read-only |
| Outline or structure | deep | clear artifact shaping | retrieve constraints; stage plan only |
| New prose | focused scene/unit design | deep | retrieve then stage |
| Continuation | focused next movement | deep continuity-owned prose | deep retrieval and handoff |
| Diagnosis | identify deepest failed layer | express evidence and repair target | read-only evidence |
| Revision | preserve intention and causal/formal role | narrow or broad repair | retrieve corrections; stage delta |
| Project import | organize uncertainties and relationships | express summaries clearly | deep source mapping and extraction |
| Fact query | minimal inference | concise answer | deep authority retrieval |

## 2. Core I contract

Core I receives evidence and decides what the work or unit is doing. It may:

- select a narrative engine;
- generate premise, pressure, branch, character strategy, relationship movement, event network, or formal arrangement;
- distinguish story chronology from reveal order;
- estimate narrative space;
- diagnose missing causality, perception, relation, implication, or form;
- compare options without promoting one to canon.

Core I returns a decision packet, not an encyclopedia:

```text
requested artifact:
dominant engine and promise:
entry evidence and constraints:
meaningful movement:
choice, reorientation, recurrence, or formal operation:
exit/residue:
uncertainty and non-canonical options:
```

For action-driven work, movement may be attempt and answering force. For voice-, atmosphere-, idea-, or form-driven work, it may be changed interpretation, accumulated association, institutional consequence, or rearranged authority. Do not invent conflict solely to fill the packet.

## 3. Core II contract

Core II chooses how the reader encounters the selected movement. Its carriers include:

- dramatized scene;
- narrative summary;
- ellipsis or transition;
- reflection or interior sequence;
- exposition attached to use or consequence;
- dialogue, monologue, or collective speech;
- letter, diary, testimony, transcript, record, list, annotation, or found document;
- montage, recurrence, frame, or other project-defined form.

Core II preserves:

- viewpoint or narrator ownership;
- target-language idiom and cultural register;
- knowledge and access boundaries;
- character voice and listener permission;
- material, social, emotional, and formal residue;
- ordinary connective prose around precise moments;
- the requested length, format, and revision scope.

Core II does not solve a broken premise by polishing sentences, reproduce Core I's notes in prose, or display its checklist inside the manuscript.

## 4. Core III contract

Core III owns project evidence, not creativity in general. It:

- resolves the target project and source authority;
- retrieves the smallest constraining packet;
- separates accepted text, confirmed notes, summaries, plans, drafts, branches, and research;
- maintains current state, open obligations, author corrections, project voice, and retrieval cues;
- stages proposed deltas;
- settles only accepted changes;
- keeps every fiction project isolated.

Core III has four operating profiles:

| Profile | Use | Typical persistence |
|---|---|---|
| Ephemeral | one-off idea, short passage, analysis without project continuity | no files; return assumptions in the answer |
| Minimal | short fiction or compact project with repeated work | source map, adaptation profile, compass, working state, core characters/events, unit ledger |
| Standard | standalone novel, novella, series, or regular serial | full relevant domains, profiles, ledgers, structure, summaries as needed |
| Large | fragmented, multi-volume, or million-character corpus | standard profile plus summary ladder, sharding, retrieval cues, and optional SQLite locator |

Profiles control retrieval and maintenance, not the richness or value of the fiction. Existing project structure outranks the bundled blank template.

## 5. Task packet

Core III passes Core I and II only material that can alter the task:

```text
project and authority:
request and output boundary:
adaptation profile and dominant engine:
author intent and protected choices:
exact source range or current handoff:
active characters, knowledge, relationships, body, resources:
active world/form constraints:
open obligations due now / protected for later:
voice and correction evidence:
uncertainties and conflicts:
```

The packet is temporary. It does not move project facts into the installed Skill. Retrieved knowledge constrains prose; it does not create an exposition quota.

## 6. Delta packet

After Core II produces the artifact, return to Core III:

```text
artifact status: analysis | proposal | draft | accepted
source pointer:
facts or states changed:
relationships, knowledge, body, resources, objects, locations changed:
threads opened, advanced, settled, or deliberately untouched:
craft feedback and its evidence:
conflicts or unresolved assumptions:
next-task handoff:
```

For analysis and unaccepted work, report or stage the packet only. For accepted work, settle each item once in its natural owner.

## 7. Routing by task

### Start from zero

Core III holds explicit seeds and unknowns. Core I selects the minimum engine, pressure, character or narrator ownership, and opening possibility. Core II produces only the requested artifact. Core III records confirmed seeds only if persistence is in scope.

### Expand or outline

Retrieve neighboring canon. Core I creates connected possibility rather than category fill. Core II shapes a readable outline, table, or note. Core III keeps alternatives non-canonical.

### Draft or continue

Retrieve exact predecessor evidence when continuity matters. Core I defines the next movement. Core II chooses the correct carrier and writes. Core III stages the factual and craft delta.

### Review or revise

Core III retrieves accepted intent, text, and corrections. Core I identifies the deepest failed layer and the role that must survive. Core II performs the smallest sufficient repair. Core III records only accepted feedback-derived learning.

### Import or recover

Core III maps sources and statuses first. Core I reconstructs causal, relational, perceptual, and formal architecture without silently choosing among contradictions. Core II expresses summaries and handoffs. No manuscript rewriting occurs unless separately requested.

### Transform form, language, or audience

Core III retrieves protected meaning and source status. Core I decides what must change when medium, language, viewpoint, age range, or release mode changes. Core II rewrites idiomatically in the new form. Core III does not overwrite the source version unless explicitly authorized.

## 8. Ambiguity and conflict

Use authority before elegance. If sources conflict:

1. preserve both claims and their sources;
2. identify which choice affects the requested artifact;
3. apply an explicit author correction or accepted-manuscript priority when available;
4. ask only when the unresolved choice materially changes the result;
5. keep any working assumption labeled and reversible.

Do not let Core I choose the most dramatic fact, Core II blend versions into smooth prose, or Core III mark a plausible inference as confirmed.

## 9. Stop rules

Stop loading when the packet can constrain the task. Stop designing when the requested artifact has enough renewable possibility. Stop revising when the observed failure is gone and regression checks pass. Stop settlement at the boundary of accepted evidence.

More structure, prose, memory, references, or NG rules are not automatically better. Each core should leave room for the other two and for the author.

## 10. Three-core audit

Before delivery, ask:

1. Did Core III retrieve the correct project and authority without leaking another project?
2. Did Core I choose the work's actual engine rather than a familiar genre formula?
3. Did Core II use the right carrier rather than dramatizing or summarizing everything?
4. Does the artifact preserve language, viewpoint/narrator, character, and form ownership?
5. Are options, forecasts, and drafts still non-canonical?
6. Is the delta proportional and evidence-backed?
7. Did the user receive the requested artifact rather than the internal three-core report?

If these pass, do not add a second framework merely to appear comprehensive.
