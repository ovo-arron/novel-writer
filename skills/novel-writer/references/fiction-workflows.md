# Fiction Workflows

Use this reference to choose a complete but lightweight workflow for creating, expanding, organizing, drafting, continuing, reviewing, or revising a novel. Respect the author's existing files and terminology; the story domains are conceptual and do not require a particular application or database.

## 1. Three cores and project memory

Every NW task uses the same loop:

```text
Core III retrieve → Core I conceive/reason → Core II express/draft
→ Core III audit, stage, and settle accepted learning
```

Core I and Core II are universal, read-only frameworks. They may receive project facts for the current task, but they never store those facts. Core II expresses outlines, reviews, and bible entries clearly when manuscript prose is not requested. Core III remains read-only for analysis-only work and may begin empty for a new novel. Core III records one adaptation profile, one compass, and up to eight story domains:

Read `three-core-orchestration.md` when a request crosses several task modes. All three cores participate at variable depth; do not produce three equal reports or initialize full memory merely to prove that the loop ran.

1. **Story compass（创作罗盘）** — reader promise, theme pressure, genre contract, tone, viewpoint, growth principle, reference mechanisms, and boundaries.
2. **Worldbuilding（世界观）** — geography, peoples, politics, law, economy, class, culture, history, religion, and ordinary life.
3. **Systems（规则体系，可选）** — repeatable social, legal, technical, medical, linguistic, temporal, magical, progression, and terminology rules.
4. **Factions（组织势力）** — states as actors, courts, sects, clans, armies, schools, guilds, churches, companies, and networks.
5. **Locations（地点空间）** — regions, settlements, buildings, roads, routes, access, distance, layout, and current condition.
6. **Events and plot（事件剧情）** — historical and manuscript events, causes, plans, arcs, scenes, aftermath, timeline, and open threads.
7. **Items（物品资源）** — possessions, tools, documents, currency, medicine, weapons, relics, artifacts, custody, condition, and quantity.
8. **Living world（生物生态，可选）** — animals, plants, fungi, disease, ecosystems, nonhuman beings, constructs, and anomalies.
9. **Characters（人物关系）** — OC design, personality in action, values, wants, knowledge, body, relationships, voice, behavior, growth, and OOC control.

`continuity.md` governs authority, retrieval, conflict resolution, and settlement across all nine. `project-memory.md` governs per-novel storage, adaptive craft learning, initialization, and isolation. The compass is author intent, not fictional-world canon.

## 1A. Adapt the framework to the work

Read `adaptation-router.md` when the project's form is new, mixed, unknown, research-sensitive, multilingual, short, or non-serial. Establish only the choices that affect the task:

1. short story, novella, standalone, series, serial, or another author-defined form;
2. complete, periodic, episodic, interactive, or unknown release mode;
3. viewpoint, chronology, document form, and accepted unit;
4. primary story engine and genre promise, with secondary promises ranked;
5. realist, historical, speculative, alternate, surreal, or allegorical relation to reality;
6. target language, cultural register, and research boundary;
7. required, conditional, and inactive memory domains.

Do not activate serial hooks, volume maps, advancement ladders, mystery reveals, romance beats, invented lore, or an ecology catalog unless this work needs them. The same Core I–III loop remains active; only its task packet changes.

## 2. Start a novel from zero

Do not demand a complete encyclopedia. Build a minimum viable story foundation:

1. Preserve the author's desired experience, form, genre hierarchy, language/register, boundaries, and uncertain choices.
2. Select a renewable narrative engine: action, character strategy, relationship, investigation, voice, atmosphere/place, idea/institution, form/document, progression, or a project-defined alternative. Add opposition only when the engine requires it.
3. Create the protagonist's decision core and one relationship that can change.
4. Establish only the social/material world and any system, faction, or location pressure needed for the opening and renewable engine.
5. Design the first causal event chain and a larger opposing future.
6. Add an item or organism only if it affects the opening, identity, livelihood, ecology, or future conflict.
7. Offer a small number of non-canonical branches for major unresolved choices.
8. Produce the requested artifact: concept, bible seed, outline, opening scene, or chapter—not all of them unless asked.
9. If persistent project memory is in scope, initialize only the blank structure and settle confirmed seeds; leave unknown fields empty.

Mark assumptions and proposals. Do not decide uncertain identity, cosmology, power, or ending merely to make the plan look complete.

## 3. Expand a setting or add material

When asked to add a country, institution, magic rule, artifact, species, historical event, faction, or location:

1. retrieve neighboring canon;
2. identify the story need or world pressure;
3. create the smallest useful entry in the matching domain;
4. test two or three real cross-effects;
5. check character, timeline, economy, law, ecology, and plot contradictions only where relevant;
6. label the addition proposal until accepted;
7. state what becomes possible, harder, costlier, or newly contested.

Do not add lore whose only function is sounding complete. A harmless flavor detail may remain harmless; a powerful rule needs consequences.

## 4. Design plot, arcs, chapters, or scenes

1. Retrieve current character states, world constraints, open threads, resources, and recent residue.
2. Define the practical objective and incompatible action.
3. Build pressure → attempt → resistance → choice/failure → changed exit → residue.
4. Check the opposition's independent aim and response.
5. Decide reader information separately from world chronology.
6. Write a reader-visible signal separately from the author-only spoiler: the signal states what the chapter lets the reader notice or worry about; the spoiler states the hidden cause or future answer and never enters reader-facing prose by accident.
7. Estimate the event span from necessary reader-experienced movements; test whether compression would hide agency or aftermath and whether expansion merely repeats the same question.
8. Map one dominant movement and changed exit state to each planned chapter, then review the event inside three-chapter, eight-to-twelve-chapter, arc, volume, and whole-story windows.
9. Test deletion, swap, causality, and continuity.
10. For alternate directions, isolate branches and keep them non-canonical.

Plans guide future choices; they do not force characters to deliver prewritten themes.

Read `structural-architecture.md` before planning several parts or volumes, weaving several plot lines, designing nonlinear revelation, rebuilding a weak middle, or reverse-outlining existing prose. Use its structure map and thread ledger to connect parts and sequences through inherited conditions, causal edges, independent futures, collisions, and settlements. Read `plot-and-pacing-engine.md` for event-to-unit estimates, expansion/compression tests, rolling horizons, and capacity calculations. `story_scale.py` tells how many chosen unit containers a target length permits; it never supplies causal material.

## 5. Create or organize characters

1. Build decision core before biography detail.
2. Record competence and blind spot together.
3. Create relationship permissions directionally.
4. Establish vocabulary sources and explanation thresholds instead of catchphrases.
5. Separate facts, beliefs, secrets, body, and resources.
6. Define a growth test rather than a guaranteed arc.
7. Run the OOC gate against any planned decisive action.

If organizing an existing cast, extract evidence from accepted prose. Do not overwrite contradictory evidence with a cleaner invented profile; report the contradiction.

## 6. Draft new prose

Before drafting, load only:

- relevant character entries and current states;
- the last scene or entry state;
- the facts that constrain this unit's action, perception, relation, knowledge, voice, or form;
- the selected carrier: scene, summary, ellipsis, reflection, exposition, document, montage, or a project-defined form;
- one genre craft target;
- natural prose guidance;
- dialogue guidance if spoken exchange is sustained.

Retrieve those constraints through Core III, choose the causal, relational, perceptual, atmospheric, intellectual, or formal movement in Core I, then realize it through the correct carrier in Core II. Do not recite retrieved bible facts. After drafting, run one evidence-based prose scan and the OOC gate; do not apply the entire NG library while composing. Stage a compact memory delta without promoting it to canon.

## 7. Continue an existing manuscript

1. Resolve the novel's project memory and read the author's manuscript and latest corrections before summaries.
2. Recover current time, location, cast, bodies, resources, knowledge, relationships, and open threads.
3. Separate canon from outline and discarded alternatives.
4. Identify the immediate unfinished action and emotional/material residue.
5. Design the next causal movement without resetting personalities or conditions.
6. Draft in the established language, viewpoint, register, and formatting.
7. Audit continuity, OOC, and local prose evidence.
8. Stage the resulting delta; after author acceptance, settle only actual changes across the affected memory domains and craft profile.

Never continue from a synopsis alone when the relevant prose is available.

## 8. Review, revise, and remove AI-mechanical writing

Choose the level before editing:

- lore contradiction → repair the lowest-authority bible or plan layer;
- OOC action → repair motive, knowledge, relationship, pressure, or transition;
- plot problem → repair causal event design;
- scene problem → repair activity, resistance, information order, or aftermath;
- dialogue problem → repair oral order and speaker ownership;
- prose problem → repair one recurring symptom;
- author line feedback → preserve liked wording and confirmed facts.

Use at most three high-impact craft categories per pass and one dialogue category. Humanization must improve ownership, causality, specificity, and variation without adding random fragments, slang, sensory clutter, or errors.

Use project craft memory as evidence, not a house-style generator. Explicit author corrections may update it immediately within scope; repeated accepted manuscript patterns may become observations; unaccepted revisions do not teach future prose.

## 9. Organize a story bible

Respect an existing project structure. Choose ephemeral, minimal, standard, or large memory depth from `project-memory.md`. If the author asks for a new persistent NW structure and none exists, use the blank superset seed in `assets/project-memory/`; inactive files may remain empty:

```text
.novel-writer/
  INDEX.md
  adaptation-profile.md
  story-compass.md
  working-state.md
  source-map.md
  author-profile.md
  craft-profile.md
  learning-log.md
  unit-ledger.md
  event-ledger.md
  pacing-plan.md
  structure-map.md
  thread-ledger.md
  retrieval-cues.md
  quality-ledger.md
  summaries/
    chapters/
    arcs/
    volumes/
  domains/
    worldbuilding.md
    systems.md
    factions.md
    locations.md
    events-and-plot.md
    items.md
    bestiary.md
    characters.md
```

Initialize it with `scripts/init_project_memory.py <project-root>` only when file creation is in scope. Each memory capable of constraining future writing should carry a status and source. Use stable names and aliases; cross-link only materially connected entries. Keep plans and alternate branches outside canon facts.

When the project becomes large or fragmented, read `long-form-memory.md`; shard ledgers and domains by natural story boundaries, maintain unit/arc/part-or-volume summaries, and optionally build the local locator with `project_archive.py`. The index may be regenerated and never outranks the manuscript. For a short story or novella, omit unused summary levels and empty domains instead of performing database theater.

When the manuscript contradicts the bible, verify whether the manuscript is accepted and whether the author issued a later correction. Do not silently reconcile incompatible versions.

## 10. Query, resume, and recover

For a fact question, retrieve the narrowest authoritative source and include uncertainty, status, and source pointer. For an integrated question, trace the causal path across only the affected domains. Never answer from a compressed note when the relevant accepted manuscript is available and the wording matters.

When resuming after an interruption:

1. resolve the project root and authoritative manuscript;
2. read `INDEX.md`, `source-map.md`, `adaptation-profile.md`, and `working-state.md`;
3. identify the last accepted unit and any pending, rejected, or partially settled work;
4. compare changed files with the last scan rather than rereading everything;
5. rebuild the smallest continuation packet;
6. report unresolved conflicts before drafting through them.

Run a lightweight memory health check when continuity feels unreliable: missing source pointers, duplicate facts, stale working state, accepted units without ledger entries, contradictory statuses, unresolved pending deltas, or a craft rule supported only by generated text. Repair the lowest-authority layer first. Read `references/serial-production.md` only when serialized production, chapter lifecycle, or rolling reader memory is active.

## 11. Delivery contract

- Return the artifact requested, not every internal worksheet.
- State assumptions, proposals, canon conflicts, and unresolved choices clearly.
- Preserve author language, formatting, liked wording, and project terminology.
- Do not write files unless creation or modification is part of the request.
- Never write one novel's memory into the installed skill or another novel's project.
- When modifying project files, report exact files and distinguish proposals from canon changes.
- When asked only to diagnose or score, do not rewrite.
- Do not claim a setting, chapter, or revision is complete when unresolved blocking contradictions remain.
