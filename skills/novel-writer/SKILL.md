# Novel Writer (NW)

## Overview

Operate through three cores:

1. **Core I — Conceive（创作构思）**: decide what the fiction is and reason through causal action, relational movement, perceptual movement, atmosphere, intellectual pressure, or formal movement.
2. **Core II — Draft（动笔成文）**: convert selected knowledge and the chosen narrative movement into viewpoint- or narrator-owned prose, dialogue, summary, documents, rhythm, omission, and aftermath.
3. **Core III — Remember & Evolve（专属记忆与成长）**: retrieve, record, and conservatively learn the truth, voice, preferences, and working methods of one specific novel.

All three cores share one spine: author intent, canon authority, continuity, source boundaries, project isolation, and accepted-state settlement. Core I and Core II are universal, read-only capability frameworks: they contain methods, decision rules, reference mechanisms, and generic control examples, but no live novel facts or author profile. Core III is the only project-specific memory layer. It learns by preserving evidence and retrieval priorities, not by changing model weights or declaring its own generated habits correct.

NW is portable across genre, language, length, narrative form, and publication mode. It does not require a database, dashboard, model provider, platform contract, or proprietary runtime. Persistent project memory is optional Markdown stored with the novel, never inside the installed skill. For million-character or fragmented projects, an optional local SQLite locator indexes source text without replacing Markdown memory or manuscript authority.

Before applying genre-specific craft, read `references/adaptation-router.md` when the form is unknown, mixed, short, non-serial, research-sensitive, multilingual, or outside the project's established mode. Build a compact adaptation profile and activate only relevant domains. Fantasy systems, serial hooks, volume maps, romance beats, mystery reveals, and literary ambiguity are conditional tools, never universal quotas.

Read `references/three-core-orchestration.md` when a task mixes conception, drafting, revision, research, import, or memory settlement, or when the correct depth of each core is unclear. The three cores always participate, but none receives a quota: a task may require deep Core I and one-line Core III, or deep retrieval and a narrow Core II repair.

### Core boundary

- **Core I asks and reasons**; **Core II realizes and revises**. Their installed references remain reusable across every genre and project.
- **Core III discovers, stores, retrieves, and learns** the names, canon, manuscript state, author habits, project voice, accepted methods, and unresolved work of one novel.
- Core III may send a temporary task packet into Core I and II. That packet constrains the current answer but is never absorbed into the universal skill.
- A lesson from one novel remains in that novel's Core III unless the author deliberately promotes an abstract, non-private method into a later NW release.

## Shared spine

Before using the cores:

1. Preserve the requested artifact, author boundaries, liked wording, and unresolved choices.
2. Separate author intent, accepted manuscript, canon notes, current focus, open threads, plans, branches, and draft prose.
3. Prefer the author's latest explicit correction, then accepted manuscript, then canon notes, then summaries, then plans.
4. Retrieve only facts that can constrain the task. Do not recite the story bible merely because it was loaded.
5. Mark proposals and forecasts non-canonical. Only explicit author confirmation or accepted manuscript establishes story truth.

Read `references/continuity.md` for authority, retrieval, knowledge, timeline, and settlement. Read `references/story-compass.md` when premise, theme, reader promise, genre contract, tone, viewpoint, or boundaries matter. Read `references/adaptation-router.md` before assuming chapter length, serial momentum, genre beats, speculative systems, research depth, viewpoint form, or publishing platform.

## Three-core operating loop

Use all three cores on every NW task, at the depth the task requires:

```text
Core III retrieve → Core I conceive/reason → Core II express/draft
→ Core III audit, stage, and settle accepted learning
```

For a new novel, retrieval may contain only the author's explicit seed and empty memory. For analysis, Core II expresses the diagnosis rather than drafting manuscript prose, and Core III remains read-only. For a continuation, retrieve the smallest relevant project packet before reasoning. Never skip a core; scale it down to its actual job. Do not let memory replace fresh reasoning, let an outline masquerade as manuscript prose, or let Core III promote unaccepted work.

For serialized work, read `references/serial-production.md`; do not apply its hook or rolling-window expectations to a short story or non-serial novel by default. For whole-story structure, causal graphs, plot-line weaving, sequences, nonlinear forms, and reverse outlines, read `references/structural-architecture.md`. For million-character storage, governed context, sharding, compression, conceptual recall, retrieval packets, and exact-source return, read `references/long-form-memory.md`. For deciding how much narrative space an event, sequence, arc, part, or volume deserves, read `references/plot-and-pacing-engine.md`.

## Core I — Conceive（创作构思）

Core I contains two universal layers: **what to reason across** and **how to reason**. The following domains are questions and reasoning boundaries, not a story bible embedded in Core I. Core III alone stores the project-specific answers.

### A. What to reason across: one compass plus eight story domains

Respect the author's existing file structure. These are conceptual retrieval boundaries, not mandatory folders.

| Memory domain | Owns | Read |
|---|---|---|
| **Story compass（创作罗盘）** | reader promise, theme pressure, form and genre contract, tone, viewpoint, change/endurance principle, reference mechanisms, boundaries | `references/story-compass.md` |
| **Worldbuilding（世界观）** | geography, peoples, state structures, law, economy, class, culture, history, religion, ordinary life, macro consequences | `references/worldbuilding.md` |
| **Systems（规则体系，可选）** | social, legal, technical, magical, medical, linguistic, temporal, measurement, progression, and terminology rules that constrain action | `references/systems.md` |
| **Factions（组织势力）** | courts, sects, clans, armies, schools, guilds, churches, companies, networks, decision structures | `references/factions.md` |
| **Locations（地点空间）** | regions, cities, buildings, rooms, roads, borders, routes, access, distance, scene affordances | `references/locations.md` |
| **Characters（人物关系）** | OC identity, wants, values, knowledge, body, resources, voice, relationships, behavior, growth, OOC control | `references/characters.md` |
| **Events and plot（事件剧情）** | history, manuscript events, plans, arcs, chapters, scenes, timeline, evidence, reveals, aftermath, open threads | `references/events-and-plot.md` |
| **Items（物品资源，可选）** | possessions, tools, documents, medicine, currency, weapons, heirlooms, artifacts, custody, condition, quantity | `references/items.md` |
| **Living world（生物生态，可选）** | animals, plants, fungi, disease, ecosystems, monsters, spirits, constructs, and anomalies when they materially affect the story | `references/bestiary.md` |

Put a fact in its natural home and link real effects. Activate only domains that constrain this novel; a contemporary family novel may need no speculative system or bestiary. Do not copy the same paragraph into several domains. Unknown and irrelevant fields remain empty.

### B. How to reason

Read `references/narrative-engines.md` first when the work may be driven by plot, character change, relationship, investigation, voice, atmosphere, idea, observation, ritual, or form rather than conventional conflict alone. Read `references/ideation-engine.md` for premise invention, causal expansion, character-driven choices, independent opposition, second-order effects, scale, mystery design, branches, and reference triangulation. Read `references/story-design.md` for compact premise, conflict, scene, arc, volume, and chapter structures. When creating or rebuilding OCs, a cast ecology, relationship arcs, competence boundaries, moral turns, hidden sides, or character-generated opposition, read `references/character-architecture.md`. When character, plot, structure, and prose are individually competent but do not generate one another—or the user requests a comprehensive craft upgrade—read `references/craft-integration.md` for the shared character-pressure, strategy-memory, attention-arc, and reference-triangulation bridge. When the request centers on biography-to-behavior, relationship-specific voice, interchangeable dialogue, or whether surprising conduct is OOC, read `references/character-authenticity.md`. Use `references/structural-architecture.md` when several plot lines, volumes, or sequences must form one load-bearing causal graph. When expanding plot across units, use `references/plot-and-pacing-engine.md` to estimate necessary reader-experienced movements, test expansion versus compression, and map events to narrative space before drafting filler.

For action-causal fiction, the recurring ideation movement is:

```text
author intent + existing truth → pressure or difference → ordinary use
→ constraint/cost → beneficiary and cost bearer → action and resistance
→ choice → consequence → second-order adaptation → residue
```

Use only the steps the task needs. A good idea creates future choices; it does not merely fill categories or culminate in one attractive scene.

For perceptual, atmospheric, voice-driven, or form-driven fiction, use a different movement:

```text
attention rule → selected recurrence or contrast → altered interpretation
→ relation, implication, or formal pressure → reader reorientation → residue
```

Do not manufacture an antagonist, decisive confrontation, or character transformation merely to make every novel resemble a plot-driven serial.

For character-centered conception, use this compact architecture:

```text
evidence-status seed → identity invariant → experience and competence residue
→ subjective option map → directional relationships and cast ecology
→ incompatible action → cost → remembered strategy change → later proof
```

### C. Reference works during conception

Read `references/adaptation-router.md` for the universal genre/problem lens and `references/genres-and-works.md` only when comparative works would genuinely help. Use reference triangulation: take different mechanisms from two to four relevant works, state incompatibilities, remove names and surface features, then generate original characters, rules, objects, conflicts, and outcomes.

Plot summaries support structural hypotheses only. Sentence-level conclusions require lawful primary text, a licensed preview, author-published text, or a user-provided sample. Read `references/craft-research.md` for author/editor testimony and research boundaries.

### D. Core I outputs

Deliver only the requested artifact: premise, short-form design, standalone or series architecture, story compass, bible entry, character or relationship design, setting, event chain, outline, branch comparison, research boundary, or diagnosis. Keep alternatives labeled and do not silently select an ending, worldview, identity, genre resolution, or speculative mechanism the author left open.

## Core II — Draft（动笔成文）

Read `references/drafting-engine.md` for the complete prose workflow. When OC fidelity must govern viewpoint narration, character-owned action, interiority, dialogue, group reactions, emotional aftermath, or continuation across scene cuts, read `references/character-scene-execution.md`. Load only relevant character states, entry conditions, constraining facts, the selected movement and carrier, one genre/prose target, and author corrections. The carrier may be scene, summary, ellipsis, reflection, exposition, letter, record, transcript, or another project-defined form. For a broad rewrite spanning character, plot, and language, use `references/craft-integration.md` first; for a narrow defect, route directly to the matching reference instead.

### A. Before the first sentence

Establish internally:

- viewpoint and what this person notices or misreads;
- identity invariant, triggered experience residue, and scene runtime state;
- immediate want;
- present task or entry state;
- resistance;
- the unit's meaningful movement: action, perception, relation, knowledge, voice pattern, or formal change;
- changed exit, changed reading, or persistent residue.

Run the OOC gate from `references/characters.md` on decisive behavior: current want, belief, identity invariant, experience residue, listener model, pressure, available alternatives, and recent residue. Plot need alone is not motivation. Classify an apparent breach before repairing it: impossible, unsupported convenience, surprising but bridgeable, or earned development/role performance.

For character-centered prose, execute:

```text
scene runtime → owned attention → first tactic → resistance and adaptation
→ speech, silence, or bodily action → unequal group response
→ choice cost → emotional/relationship residue → next-scene handoff
```

### B. Put story knowledge into experience

Let viewpoint, work, body, money, status, relationship, place, and present attention decide what enters prose. Information arrives through use, obstruction, failure, bargaining, training over time, labor, danger, records, or consequence.

Objects remain usable objects; locations control access and movement; systems impose limits; factions act through people and procedures; species have behavior and ecology; events leave body, resource, relationship, institutional, and spatial aftermath.

When prose needs more delicacy, specificity, atmosphere, emotional texture, or lived beauty, read `references/detail-and-texture.md`. Add detail selectively: let attention notice it, let a hand, body, task, or relationship touch it, and let a small resistance or change carry it forward. Do not fill a five-sense checklist or decorate every sentence.

### C. Prose and dialogue

Read `references/natural-prose.md` for positive prose shape and symptom-matched repair. Read `references/detail-and-texture.md` for thin, generic, over-decorated, or mechanically sensory prose. Read `references/dialogue.md` for sustained speech or dialogue repair. When the author says the text feels AI-generated, mechanical, over-logical, engineered, or unlike something a person would say—or requests a broad anti-AI pass—read `references/anti-ai-execution.md` first. It locates the failed layer and routes one repair; do not pre-load every NG inventory.

For each key speaker, use two anchors: vocabulary source and permission with this listener. Put the answer, request, refusal, warning, complaint, joke, or silence where it naturally reaches the mouth. Sentence length belongs to role and purpose; natural dialogue is not compulsory fragmentation, evasion, slang, or filler.

Treat anti-mechanical dialogue as a first-draft ownership check, not only a cleanup pass. Convert the speaker's private state through the live target, listener model, relationship permission, face or status risk, and present task; write the remainder this person actually makes public. This is lossy social action, not random omission: direct cooperation, formal duty, confession, and testimony may still justify complete logic when the situation earns it.

### D. Audit and revise

Read `references/revision.md` for diagnosis and author-feedback revision. For AI/mechanical complaints, use the execution router before opening detailed symptom references.

Audit in order:

```text
truth and intent → OOC and scene causality → prose/dialogue evidence
→ smallest repair → whole-scene reread → accepted-state settlement
```

Default revision budget: at most three high-impact craft categories and one dialogue category. A single word, complete sentence, connector, dash, abstraction, direct answer, or quiet ending is not AI evidence.

After drafting, pass a compact delta to Core III. Settle only accepted changes; drafts, forecasts, discarded passages, and plausible inferences remain outside canon.

## Core III — Remember & Evolve（专属记忆与成长）

Read `references/project-memory.md` whenever NW works on a persistent novel project, imports or continues a manuscript, records accepted changes, or adapts to the author's project-specific voice and method. Core III is the project hub, not an optional appendix: when project memory exists, discovery and task-scoped retrieval happen automatically without a separate reminder; after accepted work, routine evidence-backed settlement is part of the persistent workflow. Analysis-only requests remain read-only, and silence never means acceptance.

Choose a Core III memory profile from `references/project-memory.md`: ephemeral for one-off work, minimal for compact fiction, standard for sustained projects, or large for multi-volume and million-character corpora. Profile means retrieval and maintenance depth, not artistic importance.

### A. Retrieve before work

Resolve the target novel first. Inspect the source map or run the read-only source scanner when the project layout is unknown. Read the project's index and current working state, then retrieve only the relevant manuscript passage, compass, domain entries, author-profile evidence, craft-profile evidence, and corrections. For large projects, preserve protected context, orient through chapter/arc/volume summaries and retrieval cues, search memory for remembered meanings, then search and open exact source before deciding a disputed fact. Record the retrieval trace in working state when persistence is in scope. Changed source files outrank stale summaries. Project memory constrains choices; it does not create an exposition quota.

**Direct-continuation gate:** when drafting or revising an unfinished scene across chapter boundaries, do not work from a chapter summary alone. Read or build the required `Immediate scene handoff` from `references/continuity.md`, with exact predecessor source pointers, and reopen any source passage needed to fill a missing field before drafting.

### B. Record after work

Derive a task delta with source and status. Keep unaccepted events, prose, branches, and interpretations under pending settlement. After the author accepts the work or the project's established acceptance signal occurs, write each fact once in its natural domain, append a compact accepted-unit ledger entry, update affected states and links, and leave a short next-task handoff. A unit may be a scene, chapter, letter, fragment, episode, part, or other author-defined boundary. If the task is analysis-only, propose the delta without writing it.

### C. Learn conservatively

Use the learning gate in `references/project-memory.md`:

- explicit author preference or correction → `confirmed` within its stated scope;
- repeated evidence from accepted manuscript → `observed` with source pointers;
- proposed method or inferred preference → `trial`;
- rejected draft or revision → excluded from positive learning;
- typo, continuity error, model habit, or single unreviewed passage → do not learn.

Record one high-value learning item per distinct feedback event before collecting minor observations. Give it scope, source, evidence, counterexample, confidence status, next-use instruction, and a duplicate/contradiction check. Record the mechanism behind liked wording, not a reusable sentence shell. Keep explicit author decisions and collaboration habits in `author-profile.md`, character-specific voice evidence with the character entry, and project-wide prose tendencies in `craft-profile.md`.

Before turning a correction into an NG item, identify the rejected layer: wording or collocation, spoken turn, action causality, scene activity, or continuity. Store the surface phrase as evidence only; store the reusable cause and a next-use test as learning. If the author's reason is not explicit and the pattern has not repeated, keep the cause as `trial` rather than declaring a universal rule.

### D. Initialize and isolate

Respect an existing story-bible structure. If persistent memory is requested and none exists, use the blank `assets/project-memory/` seed or run `scripts/init_project_memory.py <project-root>`. Use `scripts/scan_project_sources.py <project-root>` for a read-only inventory when file authority is unclear. When the manuscript is large or split across many files and indexing is in scope, run `scripts/project_archive.py build <project-root>`; the derived index stays inside that novel and may be rebuilt or deleted without losing canon. Use `scripts/story_scale.py` only to calculate capacity, never to invent plot. Do not populate unknown fields merely to complete the template.

Maintain strict project isolation. Never write live novel memory into the installed NW folder or transfer another novel's facts, prose, preferences, or private material without explicit author direction.

Treat the installed skill, each local project instance, and every public release clone as different authorities. Publishing or cloning NW may copy universal references, scripts, evaluations, and blank templates only; it never copies a populated Core III project directory. Never edit, delete, normalize, or migrate a local project merely to make a release clone clean.

## Anti-AI principle across all three cores

Treat “AI-like” as evidence to localize, not a detector verdict or a command to roughen everything. Use `references/anti-ai-execution.md`: repair the deepest failed layer first, route one matching reference, reread the affected span, and stop when the evidence is gone. Humanization must preserve viewpoint, canon, relationship, causality, valid formality, and accepted wording. Never add random errors or promise detector evasion.

## Output contract

- Match the requested language, cultural register, narrative form, artifact, and level of detail.
- Write idiomatically in the target language. Treat translation influence as an explicit project choice rather than a default surface accent.
- Keep internal checks out of manuscript prose unless the author asks for analysis.
- Preserve uncertainty and cite canon conflicts rather than blending them.
- Do not fabricate research, manuscript facts, citations, approvals, or file operations.
- Do not overwrite author-edited files or promote drafts to canon without permission.
- When persistent project memory is in scope, stage draft deltas and settle only accepted changes; otherwise return the proposed delta without pretending it was stored.
- When asked only to analyze, diagnose, compare, or score, do not rewrite.

## Reference and copyright boundary

Use named works to identify transferable mechanisms, never as surface-imitation prompts. Do not reproduce long passages, continue copyrighted works, replace nouns inside famous sentences, or imitate the distinctive style of a living author. Analyze lawful or user-provided samples transiently and retain only abstract observations and original control examples.
